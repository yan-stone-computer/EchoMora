# EchoMora 5 分钟教程

这个教程不要求 API Key。目标是让你亲眼看到五件事：写入、抽取、召回、隔离、遗忘。

## 启动

```bash
python -m echomora --open
```

如果浏览器没有自动打开，访问 `http://127.0.0.1:8765`。

## 第 1 步：写入

发送：

```text
请记住：我不吃甜食，最近在减脂。
```

观察右侧：

- “本轮召回”出现一条刚写入记忆。
- 记忆库显示重要性、固定保护和状态。
- 图谱出现“小岚”和“甜食/减脂”相关节点。

系统实际上会生成两条候选：一条用户明确要求固定的完整承诺，一条“不吃甜食”的偏好事实。这会略微增加重复度，但 MMR 会在召回时降低相似记忆的奖励。

## 第 2 步：换一种问法

发送：

```text
我忘了，为什么你总拦着我吃甜的？
```

问题里没有原句中的“请记住”，召回仍然找到了偏好记忆。这是中期向量层在起作用。

再发送：

```text
甜食这件事，你还知道什么？
```

图谱中的“甜食”节点可以把关联记忆拉回上下文。这是 GraphRAG 补充向量检索的部分。

## 第 3 步：加入情绪

发送：

```text
今天项目终于过审了，我特别开心。
```

右侧关系条会发生小幅正向变化。它不会因此变成“绝对服从模式”，下一轮仍按同一套事实和隐私规则回答。

## 第 4 步：验证用户隔离

把右上角当前发言者从“小岚”切到“小北”，发送：

```text
你知道甜食那件事吗？
```

小北只能看到群共享记忆和本人私有记忆，不能召回小岚的减脂记录。这不是靠系统提示词提醒模型“别泄露”，而是在打分前就从候选集移除。

## 第 5 步：执行睡眠整理

点击“执行睡眠整理”。

- 低重要性、低可检索度记忆可能变成“已软遗忘”。
- 被标记为固定保护的记忆保持可召回。
- 关系分数轻微向中性回归。
- 原文和记忆没有被直接删除。

## 如何开启 DeepSeek

```bash
cp .env.example .env
```

在 `.env` 中填写：

```dotenv
DEEPSEEK_API_KEY=sk-your-key
DEEPSEEK_CHAT_MODEL=deepseek-chat
DEEPSEEK_EXTRACT_MODEL=deepseek-chat
```

重启服务。页面右上角会显示“DeepSeek 在线”。如果 API 超时或被限流，会自动切回离线回复，并在页面底部给出提示。

## 数据在哪里

默认数据库：

```text
data/echomora.db
```

删除这个文件或点击页面“清空演示”只会清理本地演示数据。不要把真实群聊直接放进公开仓库。

## 下一步改造建议

1. 把 `embed()` 替换为真实多语言 embedding。
2. 把 SQLite 相似度扫描替换为 pgvector / Qdrant。
3. 把抽取与夜间合并拆成异步任务。
4. 为私聊、群聊、临时会话增加不同 retention policy。
5. 接平台 webhook 前先做内容审核、频率限制与身份映射。
